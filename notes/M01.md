# M01 · Fundamentals: variables, references, pointers, const, auto

## Core ideas
```cpp
struct Point3 { double x, y, z; };      // 24 bytes, trivially copyable

Point3 p{1, 2, 3};        // value: you own a copy
Point3& r = p;            // reference: alias, must bind at init, never null, can't be re-pointed
Point3* ptr = &p;         // pointer: address, may be null, can be re-pointed, deref with -> / *
```

| | Storage | Null? | Re-point? | Typical use |
|---|---|---|---|---|
| `T` | sizeof(T) | – | – | Own the data |
| `T&` | usually an address (often optimised away) | ❌ | ❌ | Non-optional parameter / alias |
| `const T&` | address | ❌ | ❌ | Read-only parameter, no copy |
| `T*` | 8 bytes | ✅ | ✅ | Optional, non-owning observer; C APIs |

### const: read it right to left
```cpp
const Point3* a;          // pointer to const Point3  -> *a read-only, a can move
Point3* const b = &p;     // const pointer to Point3  -> *b writable, b fixed
const Point3* const c = &p;
double norm() const;      // member fn: doesn't modify *this (callable on const objects)
```
`const` has **zero runtime cost**. It's a compiler-checked promise, and missing it is a code-review red flag.

### auto deduction
| Declaration | From `const std::vector<double> v` | Notes |
|---|---|---|
| `auto a = v;` | `std::vector<double>` | **Copy** (heap alloc!), const dropped |
| `auto& b = v;` | `const std::vector<double>&` | const kept |
| `const auto& c = v;` | `const std::vector<double>&` | idiomatic read-only |
| `auto d = v[0];` | `double` | copy |
| `auto&& e = v;` | `const std::vector<double>&` | forwarding reference |

Range-for rules: `for (auto p : c)` copies, `for (auto& p : c)` modifies, `for (const auto& p : c)` reads.

## What happens in memory / cost
| Operation | Cost |
|---|---|
| Copy `Point3` | 24 B memcpy, cheap |
| Copy `std::vector<Point3>` with 1M points | malloc + 24 MB copy, **expensive** |
| Pass `const T&` | pointer-sized |
| `std::sqrt` | ~15–20 cycles; `std::pow(x, 2.0)` can be far slower than `x*x` |

## Pitfalls interviewers ask
1. **Reference/pointer into a vector + reallocation** → dangling (`push_back`, `insert`, `resize`, `reserve`).
2. **Pointer/reference into a temporary**: `f({{1,2,3}})` returning a pointer into its argument dangles after the `;`.
3. **Returning a reference to a local**: `const T& f() { T t; return t; }`.
4. **`size_t` underflow**: `v.size() - 1` on an empty vector is SIZE_MAX. Write `i + 1 < v.size()`.
5. **Signed/unsigned comparison**: `int i = -1; i < v.size()` is false.
6. **Uninitialized locals**: `int n;` and `Point3 p;` hold garbage. Use `int n{}` / `Point3 p{}`.
7. **Narrowing**: `int a = 3.7` truncates silently; `int a{3.7}` won't compile.
8. **Eigen + auto**: `auto C = A * B;` is an *expression*, not a matrix. Use `Eigen::Matrix3d C = A*B;` or `.eval()`.

## Robotics angle
- Pass clouds and poses by `const&`; return results by value (RVO/move makes that cheap).
- Hand out *indices* (not references) into growing containers like keyframe or map-point arrays.
- A nullable `const T*` return expresses "best match or none" without copying.
- Compare **squared** distances in nearest-neighbour code.

## Rapid-fire questions
<details><summary>Show answers</summary>

- *Reference vs pointer?* Reference: an alias that is never null and can't be re-pointed. Pointer: a nullable, re-pointable address.
- *What does `const` after a member function mean?* `this` is `const T*`, so the function can't modify members (except `mutable` ones).
- *Does `auto` keep const?* Not top-level const. `auto&` and `const auto&` do.
- *Why prefer `{}` initialization?* It prevents narrowing and value-initializes (zeroes) the object.
- *What's `nullptr` vs `NULL`?* `nullptr` has type `std::nullptr_t`, so overload resolution works; `NULL` is just 0.
- *What invalidates vector references?* Any reallocation, plus erase/insert at or before that position.
- *When is passing by value fine?* Small trivially copyable types (≤ 16–24 B), or when you'll copy anyway (then move).

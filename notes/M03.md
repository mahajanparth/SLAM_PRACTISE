# M03 · STL Containers: array, deque, list, pair, tuple

## Core ideas
```cpp
std::array<double, 3> v{};                 // fixed size, in-object storage (no heap), zero-init with {}
using Mat3 = std::array<std::array<double, 3>, 3>;  // 72 B value type; copy, ==, < all work

std::deque<ImuSample> win;                  // O(1) push/pop at BOTH ends + random access
win.push_back(s); win.pop_front();

std::list<int> lru;                         // doubly linked: O(1) splice/insert/erase given an iterator
lru.splice(lru.begin(), lru, it);           // move a node to the front, no allocation

std::pair<Vec3, double> normalize(const Vec3&);           // two named-ish results
std::tuple<double, std::size_t, std::size_t> maxAbs(...); // more results
auto [u, n] = normalize(v);                 // structured bindings (C++17), a copy of the pair
const auto& [val, r, c] = maxAbs(M);        // binds to the (lifetime-extended) temporary
std::tie(a, b) = f();                       // assign into existing variables
```

## What happens in memory / cost table
| Container | Layout | Random access | Push back | Push front | Insert middle | Overhead per elem |
|---|---|---|---|---|---|---|
| `array<T,N>` | inline, contiguous | O(1) | – | – | – | 0 |
| `vector<T>` | 1 heap block | O(1) | amortised O(1) | O(n) | O(n) | ~0 (slack capacity) |
| `deque<T>` | blocks + pointer map | O(1) (2 derefs) | O(1) | O(1) | O(n) | small |
| `list<T>` | heap node per elem | O(n) | O(1) | O(1) | O(1) with iterator | 2 pointers + malloc |
| `forward_list<T>` | node per elem | O(n) | – | O(1) | O(1) after an iterator | 1 pointer |

### Invalidation rules
| Container | push_back / push_front | pop at ends | insert/erase middle |
|---|---|---|---|
| vector | all if realloc, else end() | only erased + end() | at/after the position |
| deque | **iterators: all**; **refs: none** | only the erased element | all |
| list | none | only the erased element | only the erased element |

## Pitfalls interviewers ask
1. `std::array<int,3> a;` (local) is **uninitialised**. Write `a{}`.
2. `std::array` passed by value copies the whole array. Pass `const&` once it's larger than a few doubles.
3. Naming a free function `apply`/`size`/`swap` and calling it with `std` types: **ADL** can find `std::apply` and make the call ambiguous or fail.
4. Holding deque **iterators** across `push_back` is UB, while references are fine.
5. `std::list` "because I insert a lot": the cache misses usually cost more than the O(n) vector shift.
6. `auto [a, b] = pair;` copies; you need `auto&` to modify. Structured bindings can't be captured by lambdas in C++17.
7. `std::get<i>(tuple)` needs a compile-time `i`. Tuples of many fields are unreadable, so prefer a named struct for APIs.
8. `std::pair` comparison is lexicographic. That's handy for `(t, id)` keys, surprising for `(x, y)` "points".

## Robotics angle
- `std::array<double, 3/4/9/36>` for fixed-size vectors, quaternions, 3×3 rotations, 6×6 covariances in MCU or header-only code.
- `std::deque` for sliding windows: IMU buffers, keyframe windows in sliding-window VIO, odometry history.
- `std::list` + `unordered_map<key, list::iterator>` gives an LRU cache (map tiles, voxel blocks).
- `std::tuple<bool, Pose, double>` from `tryAlign()` is fine internally, but publicly a `struct AlignResult { bool ok; Pose T; double fitness; };` reads better.

## Rapid-fire questions
<details><summary>Show answers</summary>

- *`std::array` vs C array?* Same layout and cost, but it's a value type (copy, `==`), has `.size()` and doesn't decay to a pointer.
- *How is `std::deque` implemented?* An array of pointers to fixed-size blocks. Indexing is two hops.
- *Why does deque `push_back` invalidate iterators but not references?* The block map may reallocate, but the elements never move.
- *When is `std::list` right?* Iterator stability plus O(1) splice (LRU), or very large non-movable elements.
- *What does `std::tie` do?* Builds a tuple of lvalue references, used for multi-assignment and lexicographic comparators.
- *What do structured bindings bind to?* A hidden object (a copy, or a reference with `auto&`). The names alias its members.
- *Is `sizeof(std::array<double,0>)` zero?* No, it's at least 1. Every object has a nonzero size.
</details>

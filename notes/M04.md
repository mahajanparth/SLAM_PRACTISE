# M04 · Maps & Hashing: map, unordered_map, custom hash, buckets

## Core ideas
```cpp
std::map<double, Pose> buf;                     // red-black tree, sorted by key
buf[t] = pose;                                  // insert-or-assign (default-constructs first)
auto it = buf.lower_bound(t);                   // first key >= t   (upper_bound: first key > t)
if (it != buf.begin()) auto prev = std::prev(it);

std::unordered_map<int, int> counts;            // hash table
counts.reserve(n);                              // pre-size buckets, no rehash
++counts[id];                                   // [] inserts 0 if missing: perfect for counting
auto f = counts.find(id);                       // lookup WITHOUT inserting
if (f != counts.end()) use(f->second);
auto [pos, inserted] = counts.try_emplace(id, 0);  // insert only if absent
counts.insert_or_assign(id, 5);                 // overwrite
```

### Custom key + hash
```cpp
struct VoxelKey { int x, y, z;
  bool operator==(const VoxelKey& o) const { return x == o.x && y == o.y && z == o.z; } };
struct VoxelKeyHash { std::size_t operator()(const VoxelKey& k) const {
  std::size_t h = 0;
  for (int v : {k.x, k.y, k.z}) h ^= std::hash<int>{}(v) + 0x9e3779b97f4a7c15ULL + (h << 6) + (h >> 2);
  return h; } };
std::unordered_map<VoxelKey, Voxel, VoxelKeyHash> grid;
// or specialise: namespace std { template<> struct hash<VoxelKey> { ... }; }
```
Contract: `a == b` ⇒ `hash(a) == hash(b)`. The reverse doesn't have to hold; collisions are legal but slow.
`std::map` needs `operator<` (a strict weak ordering) instead: `std::tie(a.x,a.y,a.z) < std::tie(b.x,b.y,b.z)`.

## What happens in memory / cost table
| | `std::map` | `std::unordered_map` | sorted `std::vector` |
|---|---|---|---|
| Structure | RB-tree, 1 node/elem (3 ptrs + color) | bucket array + linked nodes | contiguous |
| find / insert | O(log n) | avg O(1), worst O(n) | O(log n) / O(n) |
| Ordered iteration, lower_bound | ✅ | ❌ | ✅ |
| Iterator invalidation on insert | none | **all iterators if rehash** (refs stay valid) | all if realloc |
| Memory per elem | ~32–48 B + payload | ~16–24 B + bucket slot + payload | payload |
| Cache behaviour | pointer chasing | 1–2 misses | best |

Load factor = size / bucket_count. When it exceeds `max_load_factor()` (1.0 by default), the table rehashes: roughly doubles the buckets and reinserts everything in O(n).

## Pitfalls interviewers ask
1. `m[key]` **inserts** on lookup, and doesn't compile on a `const` map. Use `find`/`count`/`at`.
2. `insert` does **not** overwrite an existing key. Use `[]=` or `insert_or_assign`.
3. Weak hashes (`x ^ y ^ z`, `x + y + z`) turn O(1) into O(n). Signed multiply in a hash can overflow, which is UB, so use unsigned.
4. `static_cast<int>(x / v)` truncates toward zero, which puts negative coordinates in the wrong voxel. Use `std::floor`.
5. Erasing in a loop: `it = m.erase(it);`.
6. Iteration order of `unordered_map` is unspecified. Never rely on it for output or tests.
7. Floating-point keys in `unordered_map` mean exact `==`, so 0.1 + 0.2 ≠ 0.3. For timestamps use `std::map` + `lower_bound` with a tolerance, or integer nanoseconds.
8. Pointers to `unordered_map` values survive a rehash; iterators don't.

## Robotics angle
- **Voxel hashing** (voxel grids, VDB-like maps, KISS-ICP, Voxblox) uses `unordered_map<VoxelKey, Voxel>` or a flat open-addressing map.
- **Timestamp buffers**: `std::map<int64_t ns, Pose>` + `lower_bound` gives the bracketing poses for interpolation and deskewing.
- **Landmark/keyframe tables**: `unordered_map<id, Landmark>` for O(1) id lookups from observations.
- **Counting** (observations, votes in place recognition): `++counts[id]` after a `reserve`.

## Rapid-fire questions
<details><summary>Show answers</summary>

- *How is `std::map` implemented?* A red-black tree (self-balancing BST). O(log n) operations, sorted iteration.
- *unordered_map worst case and why?* O(n), when all keys land in one bucket (bad hash or adversarial input).
- *What triggers a rehash?* size > bucket_count × max_load_factor. It invalidates iterators, not references.
- *What do you need for a custom key?* unordered: a hash plus `==`. ordered: `<` (strict weak ordering).
- *lower_bound vs upper_bound?* First key ≥ k vs first key > k.
- *How do you count without inserting on lookup?* `find`, or `count(k)` (0/1 for maps), or `contains` in C++20.
- *Why `try_emplace` over `emplace`?* It doesn't construct (or move from) the value if the key already exists.
- *Faster alternative for a static lookup table?* A sorted vector + `std::lower_bound` (contiguous, cache-friendly).
</details>

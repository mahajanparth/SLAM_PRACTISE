# M05 · Sets: set, unordered_set, multiset

## Core ideas
```cpp
std::set<int> ids(v.begin(), v.end());        // sorted + unique (RB-tree)
ids.insert(7); ids.erase(3); ids.count(7);     // O(log n)
auto it = ids.lower_bound(5);                  // first >= 5

std::unordered_set<int> seen; seen.reserve(n);
if (!seen.insert(id).second) { /* duplicate */ }  // ONE lookup for "seen before?"

std::multiset<double> win;                     // sorted, duplicates allowed
win.erase(win.find(r));                        // remove ONE copy
// win.erase(r);                               // removes ALL copies!
auto [lo, hi] = win.equal_range(r);            // all copies of r

std::set<std::tuple<int,int,int>> voxels;      // tuple has operator<, so it works as a key
std::set<Point3, ByX> byX;                     // custom comparator: must be a STRICT weak order
```

### Set algorithms (on any **sorted** ranges, vectors included)
```cpp
std::set_intersection(a.begin(), a.end(), b.begin(), b.end(), std::back_inserter(out)); // a ∩ b
std::set_difference  (a.begin(), a.end(), b.begin(), b.end(), std::back_inserter(out)); // a \ b
std::set_union / std::set_symmetric_difference / std::includes(a..., b...)              // b ⊆ a ?
```
All are O(|a| + |b|), a single merge pass.

## What happens in memory / cost table
| | `set` / `multiset` | `unordered_set` | sorted `vector` + `unique` |
|---|---|---|---|
| insert / find / erase | O(log n) | avg O(1) | O(n) insert, O(log n) find |
| ordered iteration, lower_bound, k-th smallest | ✅ (k-th is O(k) walk) | ❌ | ✅ O(1) k-th |
| memory per element | node ≈ 32 B + value | node ≈ 16 B + value + bucket | value only |
| invalidation | only the erased element | iterators on rehash | all on realloc |
| custom key needs | `operator<` / comparator | hash + `==` | `operator<` |

## Pitfalls interviewers ask
1. **`multiset::erase(value)`** erases all copies. Use `erase(find(value))`.
2. **Non-strict comparator** (`<=`) is UB in set/map/sort.
3. **Comparator defines equality**: `set<Point3, ByRange>` treats two different points at the same range as the same element and drops one.
4. **Elements are const**: to "modify", `erase` + `insert` (or `extract` the node in C++17).
5. **`std::hash<std::tuple>` doesn't exist**: write a hash, or pack into `uint64_t`.
6. **`count` then `insert`** costs two lookups. Use `insert(...).second`.
7. **`std::next(ms.begin(), k)`** is O(k): a tree isn't random access. Don't call it a log-time median.
8. Set algorithms on **unsorted** ranges give silently wrong output.

## Robotics angle
- **Feature tracking**: tracked / lost / new ids between frames via `set_intersection` / `set_difference`.
- **Visited sets**: occupied voxels, closed set in A*/BFS (`unordered_set<CellKey>`).
- **Robust statistics**: a sliding-window median (multiset or two-heap) for range spikes, wheel-odometry slip, timestamp jitter.
- **Loop-closure candidates**: a `std::set` of keyframe ids is deterministic and ordered, which keeps debugging reproducible.

## Rapid-fire questions
<details><summary>Show answers</summary>

- *set vs unordered_set?* Ordered, log n, needs `<`, vs hashed, O(1) average, needs hash + `==`, no order.
- *How do you remove one duplicate from a multiset?* `ms.erase(ms.find(v))` (check `!= end()` first).
- *Why are set elements const?* Mutating a key in place would break the tree order or bucket placement.
- *What's a strict weak ordering?* Irreflexive, asymmetric, transitive, with transitive equivalence. `<` qualifies, `<=` doesn't.
- *Complexity of set_intersection?* Linear in both sizes. Requires sorted inputs.
- *Sliding-window median options?* Multiset with a moving middle iterator, two balanced multisets, or two heaps with lazy deletion.
- *Fast dedup of a vector?* `sort` + `erase(unique(...), end())`, which is contiguous and needs no allocation per element.
</details>

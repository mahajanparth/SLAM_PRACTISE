# M06 · STL Algorithms: sort, find, transform, lower_bound, nth_element, accumulate

## Core ideas
```cpp
#include <algorithm>   // sort, stable_sort, partial_sort, nth_element, find, count_if, transform,
                       // lower_bound, upper_bound, equal_range, partition, stable_partition, remove_if, unique, min_element
#include <numeric>     // accumulate, reduce, iota, inner_product, partial_sum

std::sort(c.begin(), c.end(), [](const Point3& a, const Point3& b) { return a.z < b.z; });
auto it = std::lower_bound(t.begin(), t.end(), query);                   // first >= query (sorted!)
std::nth_element(d.begin(), d.begin() + k, d.end());                     // k-th smallest at d[k], O(n)
Point3 s = std::accumulate(c.begin(), c.end(), Point3{0,0,0}, addPts);   // init sets the TYPE
std::transform(c.begin(), c.end(), std::back_inserter(r), rangeOf);      // map
auto n = std::count_if(c.begin(), c.end(), [&](auto& p){ return p.z < -1.5; });
auto mid = std::stable_partition(c.begin(), c.end(), isGround);          // ground first, order kept
std::vector<std::size_t> idx(n); std::iota(idx.begin(), idx.end(), 0);   // 0..n-1 for argsort
auto [mn, mx] = std::minmax_element(c.begin(), c.end(), byZ);
```

### Picking the right sort-like tool
| Need | Algorithm | Cost |
|---|---|---|
| Full order | `sort` | O(n log n), not stable |
| Full order, ties keep input order | `stable_sort` | O(n log n), extra buffer |
| Top-k, sorted | `partial_sort` | O(n log k) |
| k-th element / median / top-k unsorted | `nth_element` | O(n) average |
| Split by predicate | `partition` / `stable_partition` | O(n) / O(n) with buffer |
| Min / max | `min_element` / `minmax_element` | O(n) |
| Search sorted | `lower_bound` / `upper_bound` / `equal_range` | O(log n) |
| Search unsorted | `find` / `find_if` / `any_of` | O(n) |

## What happens in memory / cost table
| Algorithm | Allocates? | Iterator category |
|---|---|---|
| `sort`, `nth_element`, `partial_sort` | no | random access |
| `stable_sort`, `stable_partition`, `inplace_merge` | tries to (temporary buffer), falls back to slower in-place | RA / bidirectional |
| `lower_bound` | no | forward (O(log n) comparisons, but O(n) steps on a list!) |
| `transform`, `copy` into `back_inserter` | via container growth | output iterator |

## Pitfalls interviewers ask
1. **`accumulate(..., 0)`** on doubles truncates to int. Use `0.0`.
2. **Writing to an empty destination** (`transform(..., out.begin(), ...)`) is UB. Use `back_inserter` or pre-size.
3. **Binary search on unsorted data** is meaningless and never diagnosed.
4. **`lower_bound` on `std::set`/`std::map`**: call the *member* `s.lower_bound(x)` (O(log n)). `std::lower_bound(s.begin(), s.end(), x)` is O(n) steps.
5. **Comparator not a strict weak ordering** (`<=`, or inconsistent with NaN) is UB, and can crash `std::sort`.
6. **`std::sort` isn't stable**. If ties matter, use `stable_sort` or add a tie-break key (`std::tie(a.d, a.idx) < ...`).
7. **`nth_element` leaves the k smallest unsorted**. Sort the first k if order matters.
8. **`std::reduce` with doubles** may reorder the additions, so results aren't bit-reproducible.

## Robotics angle
- **kNN / outlier removal**: `nth_element` on distances (k-th neighbour distance, median-based thresholds).
- **Timestamp association**: `lower_bound` + `prev` for the nearest camera/IMU stamp, or a two-pointer sweep when both streams are sorted.
- **Ground segmentation**: `stable_partition` by height or normal, keeping ring order for the next stage.
- **Centroid / covariance**: `accumulate` or a single pass. Kabsch/ICP needs the centroids first.
- **Argsort**: `iota` + `sort` on indices with a comparator over a key array. You get a permutation without moving heavy points.

## Rapid-fire questions
<details><summary>Show answers</summary>

- *What sort does `std::sort` use?* Introsort (quick + heap + insertion), O(n log n) worst case, not stable.
- *How do you find the median in O(n)?* `nth_element` at n/2 (for an even n, also take the max of the lower half).
- *lower_bound vs upper_bound?* First ≥ value vs first > value. Together they make `equal_range`.
- *partition vs stable_partition?* O(n) unstable vs stable (buffered O(n), in-place O(n log n)).
- *Why do algorithms take iterators, not containers?* Generic over containers, sub-ranges and raw arrays. The consequence is that they can't change the container's size (hence erase-remove).
- *accumulate vs reduce?* accumulate is a left fold in fixed order. reduce may reorder or parallelise and needs an associative op.
- *k smallest out of 10⁶ for small k?* `nth_element` (O(n)) or a size-k max-heap (O(n log k)), streaming-friendly.
</details>

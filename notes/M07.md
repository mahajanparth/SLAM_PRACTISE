# M07 · Functions: parameter passing, overloading, default args, RVO

## Core ideas
```cpp
double range(Point3 p);                       // by value: small, trivially copyable (≤ ~16–24 B)
void   scaleInPlace(Cloud& c, double s);      // by non-const ref: the function MODIFIES the argument
double meanRange(const Cloud& c);             // by const ref: large, read-only
void   setCloud(Cloud c) { c_ = std::move(c); }  // sink: by value + move (it's stored anyway)
Cloud  takeOver(Cloud&& c);                   // rvalue ref: caller gives up ownership
Cloud  filter(const Cloud& in);               // return BY VALUE (RVO / move)
```

### Choosing a parameter type
| Intent | Small T (int, double, Point3) | Large T (vector, string, Mat) |
|---|---|---|
| Read only | `T` | `const T&` |
| Modify caller's object | `T&` | `T&` |
| Store / consume a copy | `T` | `T` + `std::move` (sink), or a `const T&` / `T&&` pair |
| Optional / nullable | `const T*` or `std::optional<T>` | `const T*` |

### Value categories cheat
| Expression | Category | Binds to `T&` | `const T&` | `T&&` |
|---|---|---|---|---|
| `c` (named variable) | lvalue | ✅ | ✅ | ❌ |
| `Cloud(5)`, `make()` | prvalue | ❌ | ✅ (lifetime extended) | ✅ |
| `std::move(c)` | xvalue | ❌ | ✅ | ✅ |
| `c` inside `f(Cloud&& c)` | **lvalue** | ✅ | ✅ | ❌, so use `std::move(c)` again |

### Overloading and ref-qualifiers
```cpp
std::vector<Point3> apply(const Pose&, const std::vector<Point3>&);  // copies
std::vector<Point3> apply(const Pose&, std::vector<Point3>&&);       // reuses buffer
LidarScan build() const&;  // called on lvalue builders
LidarScan build() &&;      // called on temporaries / std::move(b)
```
Resolution ranking: exact match > promotion (float→double, char→int) > conversion (int→double, long→int) > user-defined.
Two conversions of equal rank mean an **ambiguous** call and a compile error.

### Default arguments
```cpp
Pose makePose(double yaw, double tx = 0, double ty = 0, double tz = 0);  // trailing only
```
Put them on the **declaration** (header) only, never repeated on the definition. They are bound statically. A virtual override
called through a base pointer uses the **base's** defaults.

## What happens in memory / cost
| Call | Cost (Cloud with 1M points = 24 MB) |
|---|---|
| `f(const Cloud&)` | pointer in a register |
| `f(Cloud)` with an lvalue | malloc + 24 MB memcpy |
| `f(Cloud)` with `std::move(c)` | 3 pointer copies (move ctor) |
| `return local;` | NRVO (0 ops) or move. Never a copy |
| `return Cloud(n);` (prvalue) | **guaranteed** elision in C++17 |
| `return std::move(local);` | forces a move, **blocks NRVO**. Avoid |
| `return param;` (by-value param) | implicit move (no NRVO possible) |
| `return rref_param;` (`T&&` param) | **copy** in C++17! Needs `std::move` |

## Pitfalls interviewers ask
1. **Returning a reference/pointer to a local** dangles. Return by value.
2. **`const T&` to a temporary member/sub-object** returned from a function, e.g. `const auto& x = getScan().ranges;`. The lifetime extension only covers the complete temporary bound directly.
3. **Named rvalue refs are lvalues**: forgetting `std::move` inside a `&&` overload silently copies.
4. **`return std::move(local)`** pessimizes, because it disables NRVO.
5. **Passing `shared_ptr` by value** on a hot path costs an atomic inc/dec. Pass `const T&` if you're not sharing ownership.
6. **Ambiguous overloads**: `f(int)` / `f(double)` with `f(3L)`; `f(Point3*)` / `f(int)` with `f(0)` vs `f(nullptr)`.
7. **Default args + virtual**: the defaults come from the static type.
8. **Out-parameters** (`void f(Cloud& out)`) were a pre-C++11 habit. Prefer returning a value or a struct/tuple.

## Robotics angle
- Callbacks: `void onScan(const LidarScan& msg)`. Never by value at 20 Hz × 100k points.
- Pipelines: `Cloud filtered = voxelize(removeGround(std::move(raw)));` lets each stage reuse the buffer.
- Builders/configs: aggregate structs with defaults (`struct IcpParams { int max_iter = 30; double eps = 1e-6; };`)
  beat 8 default arguments.
- Eigen: pass `const Eigen::Matrix4d&`, or `Eigen::Ref<const MatrixXd>` for generic blocks. Passing fixed-size vectorizable Eigen types **by value**
  was an alignment hazard before C++17.

## Rapid-fire questions
<details><summary>Show answers</summary>

- *When is pass-by-value better than `const&`?* Small trivially copyable types, or when you'd copy anyway (sink, then move).
- *Is RVO guaranteed?* For prvalues (`return T(...)`) since C++17, yes. NRVO (`return local;`) is permitted but not required. If it doesn't happen, you get a move.
- *What does `std::move` do?* Nothing at runtime. It's a cast to `T&&` that makes the object eligible for move overloads.
- *State of a moved-from `std::vector`?* Valid but unspecified (in practice empty). You can assign to it or call `clear()` on it.
- *Can you overload on return type?* No. Only on parameters, cv/ref-qualifiers of `this`.
- *Why does `f(Cloud&)` reject `f(load())`?* Non-const lvalue refs can't bind to temporaries.
- *Where do default arguments go?* On the declaration only, trailing parameters only.
- *What's a ref-qualified member function?* `T get() &&;` is only callable on rvalue objects, so it can move members out.
</details>

# M08 · Function Pointers & std::function: callbacks, type erasure, member pointers

## Core ideas
```cpp
double range(const Point3& p);                 // a function
double (*fp)(const Point3&) = &range;          // function pointer (the & is optional)
using RangeFn = double (*)(const Point3&);     // always alias it
fp(p);  (*fp)(p);                              // both call

std::function<bool(const Point3&)> keep;       // holds ANY callable with that signature
keep = [r2 = 900.0](const Point3& p) { return p.x*p.x + p.y*p.y + p.z*p.z < r2; };
if (keep) keep(p);                             // empty -> throws std::bad_function_call
```

### Member pointers
```cpp
double Point3::*axis = &Point3::z;             // pointer to DATA member (an offset)
p.*axis = 1.0;  ptr->*axis = 2.0;

struct Imu { void onSample(const Sample&); };
void (Imu::*cb)(const Sample&) = &Imu::onSample;   // pointer to MEMBER FUNCTION
(imu.*cb)(s);  (pimu->*cb)(s);                     // parentheses required
std::invoke(cb, imu, s);                           // C++17 uniform call
auto bound = [&imu](const Sample& s) { imu.onSample(s); };   // prefer this to std::bind
```

### Choosing a callable parameter type
| Parameter type | Accepts | Call cost | Storable in a container? |
|---|---|---|---|
| `R(*)(Args...)` | free functions, capture-less lambdas | indirect call | ✅ (8 B) |
| `template <class F> void f(F fn)` | anything | direct, **inlinable** | ❌ (each F is a different type) |
| `std::function<R(Args...)>` | anything copyable | indirect plus type erasure, maybe a heap alloc | ✅ (32 B on libstdc++) |
| `R (T::*)(Args...)` | a member function of T | indirect (+ this adjust; virtual-aware) | ✅ (16 B) |

## What happens in memory / cost
| Thing | Notes |
|---|---|
| Function pointer | 8 B; the call is an indirect jump, rarely inlined |
| `std::function` | Small-buffer storage (16 B on libstdc++) plus invoker/manager pointers. Larger captures → **heap allocation** at construction or copy |
| Copying a `std::function` | Copies the target (deep copy of captures); possibly allocates |
| Member function pointer | 16 B on Itanium ABI (ptr + this-adjustment) |
| `std::bind` | Works but is opaque and hard to read; lambdas are preferred |

## Pitfalls interviewers ask
1. **Calling an empty `std::function`** → `std::bad_function_call`. Calling a null function pointer is **UB**.
2. **Dangling captures in stored callbacks**: `[this]` or `[&]` registered on a bus that outlives the object.
3. **Iterator invalidation during dispatch**: a callback that unsubscribes (itself or others) while you iterate the container. Snapshot ids, re-look-up, and invoke a copy.
4. **`std::function` in hot loops**: a per-point virtual-ish call blocks inlining. Use templates for inner loops.
5. **`.*` precedence**: `obj.*pmf()` parses as `obj.*(pmf())`. Write `(obj.*pmf)()`.
6. **Capturing lambdas don't convert** to C function pointers. For C APIs pass a `void* user_data` plus a capture-less trampoline.
7. **`std::function` requires a copyable target**, so a lambda that captures a `unique_ptr` can't be stored (C++23 adds `std::move_only_function`).

## Robotics angle
- Driver → subscriber fan-out (IMU, lidar, camera) is a `std::map<id, std::function<void(const Msg&)>>`.
- Config-driven pipelines: `name -> factory` dispatch tables build filter chains from YAML.
- State machines: `std::array<void (Fsm::*)(), N>` indexed by state, or a `std::map<State, std::function<...>>`.
- C driver SDKs (e.g. vendor lidar SDKs) take `void (*cb)(const Packet*, void* user)`. Pass `this` as `user` and cast it back in a static trampoline.
- Prefer RAII subscription handles (the destructor unsubscribes) or `weak_ptr` captures to avoid calls into destroyed nodes.

## Rapid-fire questions
<details><summary>Show answers</summary>

- *Function pointer vs `std::function`?* A pointer holds only functions or capture-less lambdas and costs 8 B. `std::function` type-erases any callable but costs more and may allocate.
- *How does `std::function` store a lambda of unknown type?* Type erasure: a templated constructor builds an invoker/manager for that type and stores the object in its small buffer or on the heap.
- *What does calling an empty `std::function` do?* It throws `std::bad_function_call`.
- *How do you call a member-function pointer?* `(obj.*pmf)(args)`, `(ptr->*pmf)(args)`, or `std::invoke(pmf, obj, args)`.
- *Can a member function pointer to a virtual function dispatch virtually?* Yes. It does a virtual call through the object's vtable.
- *Why prefer templates for algorithm callbacks?* The compiler sees the concrete type, so it can inline the call.
- *How do you safely unsubscribe from within a callback?* Iterate over a snapshot of ids, re-check that each still exists, and invoke a local copy.
</details>

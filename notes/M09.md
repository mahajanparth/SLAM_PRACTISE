# M09 · Lambdas: captures, closures, generic lambdas, mutable

## Core ideas
```cpp
double max_r = 30.0;
auto inRange = [max_r](const Point3& p) { return p.x*p.x + p.y*p.y + p.z*p.z < max_r*max_r; };
cloud.erase(std::remove_if(cloud.begin(), cloud.end(),
                           [&](const Point3& p) { return !inRange(p); }), cloud.end());
```
A lambda expression creates an object of a unique, unnamed **closure class**. Roughly:
```cpp
struct __Closure {                       // what the compiler generates for [max_r](const Point3& p) {...}
  double max_r;                          // captures become data members
  bool operator()(const Point3& p) const { ... }   // const unless `mutable`
};
```

| Capture | Meaning | Safe to return / store? |
|---|---|---|
| `[]` | nothing; converts to a function pointer | ✅ |
| `[x]` / `[=]` | copy x (or everything used) **at creation time** | ✅ (unless x is a pointer) |
| `[&x]` / `[&]` | reference to x | ❌ if it outlives x |
| `[this]` / implicit via `[=]` | copy of the **pointer** `this` | ❌ if it outlives the object |
| `[*this]` (C++17) | copy of the whole object | ✅ |
| `[p = std::move(ptr)]` | init-capture (C++14): move a unique_ptr or vector in | ✅ |
| `[n = 0]() mutable` | private state that persists across calls | ✅ |

### Generic lambdas (C++14) and folds (C++17)
```cpp
auto scale = [](auto v, double s) { return v * s; };      // operator() is a template
auto allOf = [](auto... preds) {
  return [=](const auto& x) { return (true && ... && preds(x)); };  // fold expression
};
auto compose = [](auto f, auto g) { return [=](auto&& x) { return g(f(std::forward<decltype(x)>(x))); }; };
```

### mutable and state
```cpp
auto nextId = [id = 0]() mutable { return id++; };
nextId(); nextId();          // 0, 1
auto copy = nextId;          // copies the state (id == 2)
copy(); nextId();            // both return 2: independent
```

## What happens in memory / cost
| Thing | Size / cost |
|---|---|
| Capture-less lambda | 1 byte (empty class), inlinable |
| `[a, b]` with two doubles | 16 B, stored inline (stack / wherever the closure lives) |
| Calling a lambda passed as a template parameter (`std::sort(..., cmp)`) | direct call, usually **inlined** |
| Same lambda stored in `std::function` | type-erased: indirect call, possible heap alloc if captures > SBO (~16 B) |
| `[=]` capturing a `std::vector` | **deep copy** of the vector, an O(n) allocation |

## Pitfalls interviewers ask
1. **Dangling `[&]`**: returning a lambda that captured a local or parameter by reference.
2. **`[=]` in a member function captures `this`**, not the members, so it dangles if stored past the object's life (common in async callbacks).
3. **By-value capture is a snapshot**: later changes to the variable aren't seen.
4. **Forgot `mutable`**: `[n]() { ++n; }` won't compile because `operator()` is const.
5. **Stateful predicates in algorithms**: `std::remove_if` and `std::sort` may copy the functor, so don't rely on by-value state. Use `[&counter]`.
6. **Capturing a big container by value** in a hot loop is a silent O(n) copy.
7. **Each lambda has a distinct type**: `auto a = []{}; auto b = []{};` gives different types, so you can't put them in the same `std::vector` without `std::function`.
8. **Structured bindings can't be captured** in C++17 (`auto [x, y] = p; [x]{}` is an error). Use an init-capture: `[x = x]`.

## Robotics angle
- `std::sort` or `std::nth_element` over a cloud with a comparator capturing the query point (kNN, range sorting).
- `remove_if` with a capturing crop-box or range filter in a preprocessing node.
- ROS-style subscriptions: `sub = nh.subscribe(topic, [this](const Msg& m) { onScan(m); });`. The object must outlive the subscription.
- Ceres/g2o cost functors are closures in all but name: captured measurement + `operator()`.
- Thread pools take `[=]` or `[data = std::move(chunk)]` tasks, and capture-by-reference across threads is a classic race or dangling bug.

## Rapid-fire questions
<details><summary>Show answers</summary>

- *What is a closure?* The runtime object created by a lambda expression: an instance of a unique class that holds the captures.
- *When does a by-value capture copy?* When the lambda is **created**, not when it's called.
- *Can a capturing lambda be passed to a C callback `void(*)(int)`?* No. Only capture-less lambdas convert to function pointers.
- *What does `mutable` do?* It makes `operator()` non-const, so the lambda can modify its own copies of captured values.
- *Lambda vs `std::function` as a parameter?* A template parameter has zero overhead and can be inlined; `std::function` costs type erasure but gives a single, storable type.
- *How do you move a `unique_ptr` into a lambda?* With an init-capture: `[p = std::move(p)]`.
- *What does `[=]` capture in a member function?* `this` (the pointer), implicitly.
- *What's the return type of a lambda?* It's deduced from the `return` statements like `auto` (or set with `-> T`). All returns must deduce the same type.
</details>

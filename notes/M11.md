# M11 · Smart Pointers: unique_ptr, shared_ptr, weak_ptr, cycles

## Core ideas
```cpp
auto drv = std::make_unique<LidarDriver>();           // sole owner, move-only, zero overhead
std::unique_ptr<Driver> base = std::move(drv);        // Derived -> Base conversion; drv is now null
auto kf  = std::make_shared<Keyframe>(7);             // shared ownership (refcounted)
auto kf2 = kf;                                        // use_count 2 (atomic increment)
std::weak_ptr<Keyframe> obs = kf;                     // observer: doesn't keep it alive
if (auto k = obs.lock()) use(*k);                     // promote to an owner for the duration of use
```

| | Owns? | Copy | Size (x86-64) | Typical use |
|---|---|---|---|---|
| `unique_ptr<T>` | sole | ❌ (move only) | 8 B | factories, members, pimpl, RAII for C handles |
| `shared_ptr<T>` | shared | ✅ (atomic ++) | 16 B + control block | genuinely shared lifetime (map points across keyframes, async tasks) |
| `weak_ptr<T>` | no | ✅ | 16 B | back-references, caches, observers; breaks cycles |
| `T*` / `T&` | no | ✅ | 8 B | non-owning parameter ("use but don't keep") |

### Custom deleters
```cpp
struct Closer { void operator()(DeviceHandle* h) const { dev_close(h); } };
std::unique_ptr<DeviceHandle, Closer> dev(dev_open(3));          // deleter is part of the TYPE; empty functor = 8 B
std::unique_ptr<FILE, decltype(&fclose)> f(fopen("log", "w"), &fclose);   // fn-pointer deleter = 16 B
std::shared_ptr<DeviceHandle> s(dev_open(4), dev_close);          // deleter type-erased in the control block
```

### Passing smart pointers (Herb Sutter's guideline)
| Signature | Means |
|---|---|
| `void f(const Keyframe&)` / `Keyframe*` | uses the object; ownership is irrelevant (**the default**) |
| `void f(std::unique_ptr<T> p)` | takes ownership (the caller must `std::move`) |
| `void f(std::unique_ptr<T>& p)` | may reseat or reset the caller's pointer |
| `void f(std::shared_ptr<T> p)` | keeps a share (stores it) |
| `void f(const std::shared_ptr<T>& p)` | might take a share (rare) |

## What happens in memory / cost
| Thing | Cost |
|---|---|
| `make_unique` | one `new`, and the destructor is a direct `delete` |
| `make_shared` | **one** allocation: control block + object together |
| `shared_ptr<T>(new T)` | two allocations (object, control block) |
| Copy/destroy a `shared_ptr` | atomic inc/dec, around 20–50 cycles uncontended; cache-line ping-pong across threads |
| Control block | strong count, weak count, deleter, allocator (~16–32 B) |
| `weak_ptr::lock()` | atomic compare-and-swap loop |
| With `make_shared` + live `weak_ptr`s | the object is destroyed at strong = 0, but the **memory** is freed only at weak = 0 |

## Pitfalls interviewers ask
1. **Cycles**: `A ↔ B` via `shared_ptr` leaks. Make the back-edge `weak_ptr`.
2. **Two control blocks**: `shared_ptr<T>(raw)` twice → double delete. Inside a class use `enable_shared_from_this`.
3. **`shared_from_this()` in the constructor** (or on an object not owned by a shared_ptr) throws `bad_weak_ptr`.
4. **Passing `shared_ptr` by value everywhere** pays atomic traffic and hides ownership. Pass `const T&` instead.
5. **`expired()` then `lock()`**: a TOCTOU race. Just `lock()` and test the result.
6. **Deleting through a base pointer without a virtual destructor** is UB, even with `unique_ptr<Base>` (but `shared_ptr` created from `make_shared<Derived>` remembers the right deleter).
7. **`unique_ptr<T[]>`** for arrays (it calls `delete[]`). Better: `std::vector`.
8. **Capturing `shared_from_this()` in a long-lived callback** keeps the object alive forever. Capture a `weak_ptr` instead.

## Robotics angle
- SLAM maps: keyframes own map points (`shared_ptr`), and points observe keyframes (`weak_ptr`). Culling a keyframe lets the observations expire naturally.
- Sensor driver factories return `unique_ptr<Driver>`, and the node owns them in a vector.
- Message passing (ROS 2 intra-process) hands `unique_ptr<Msg>` for zero-copy, or `shared_ptr<const Msg>` to fan out to several subscribers.
- Vendor C handles (CAN socket, camera SDK, `FILE*`) belong in a `unique_ptr` with a custom deleter.
- Hot loops over points never touch `shared_ptr`. Resolve to a raw `T*` or `T&` outside the loop.

## Rapid-fire questions
<details><summary>Show answers</summary>

- *Is `shared_ptr` thread-safe?* The control block (refcount) is. The pointed-to object and the same `shared_ptr` instance are not.
- *Why `make_shared`?* One allocation, better locality, and exception-safe in function arguments (pre-C++17 ordering).
- *When does a `weak_ptr`'s memory get freed?* The object goes at strong = 0; the control block (and the `make_shared` chunk) at weak = 0.
- *Can you convert `unique_ptr` to `shared_ptr`?* Yes, from an rvalue: `std::shared_ptr<T> s = std::move(u);`. The reverse isn't possible.
- *What does `unique_ptr::release()` do?* It gives up ownership **without** deleting and returns the raw pointer, which the caller must now free.
- *How do you break a `shared_ptr` cycle?* Make one direction `weak_ptr` (usually child → parent or observer → subject).
- *Overhead of `unique_ptr` vs a raw pointer?* None with a stateless deleter. Same size, same code.
- *What is `enable_shared_from_this` for?* Getting a `shared_ptr` that shares the existing control block from inside a member function.
</details>

# M12 · OOP Fundamentals: classes, constructors, destructors, invariants, initializer lists

## Core ideas
```cpp
class Rotation2D {
 public:
  Rotation2D() = default;                                    // identity (default member inits below)
  explicit Rotation2D(double th) : c_(std::cos(th)), s_(std::sin(th)) {}   // explicit: no double -> Rotation2D
  static Rotation2D fromCosSin(double c, double s);          // named factory: normalises, handles 0
  double angle() const { return std::atan2(s_, c_); }        // const: callable on const objects
  Rotation2D operator*(const Rotation2D& o) const;
 private:
  double c_ = 1.0, s_ = 0.0;                                 // INVARIANT: c² + s² = 1
};
```
**struct vs class**: they're identical except for the default access (`public` vs `private`). Convention: use `struct` for plain aggregates with no invariant (`Point3`, `ImuSample`), and `class` when you have an invariant to protect (`Rotation2D`, `OccupancyGrid`, `UnitQuaternion`).

### Constructors
| Kind | Example | Notes |
|---|---|---|
| default | `Grid() = default;` | generated only if you declare no other constructor |
| parameterised | `Grid(int w, int h)` | establish the invariant or **throw** |
| `explicit` single-arg | `explicit Meters(double)` | prevents surprising implicit conversions |
| delegating | `Grid() : Grid(1, 1) {}` | reuse validation |
| member init list | `: w_(w), cells_(w * h)` | runs **in declaration order**; required for const, reference, and no-default-ctor members |
| default member initialiser | `double c_ = 1.0;` | used when the init list doesn't mention the member |
| static factory | `static std::optional<Grid> create(...)` | named, can fail without exceptions |

### Destructors
```cpp
~Lidar() { stopMotor(); }   // runs automatically at scope end / delete; implicitly noexcept
```
Order: the destructor body first, then members in **reverse declaration order**, then bases.

### Encapsulation & const-correctness
```cpp
double logOdds(int x, int y) const;      // read-only query: const
void   update(int x, int y, double d);   // mutator: non-const, re-establishes the invariant (clamp)
const std::vector<Point3>& points() const { return pts_; }  // no copy, no mutation from outside
mutable std::mutex m_;                   // mutable: may change even in const methods (caches, locks)
static int count;                        // one per class, not per object
```

## What happens in memory / cost
| Thing | In the object? | Cost |
|---|---|---|
| Non-static data members | ✅ (+ padding) | `sizeof` |
| Non-virtual member functions | ❌ (code; `this` is a hidden parameter) | same as a free function, inlinable |
| `static` data members | ❌ (one global) | — |
| First `virtual` function | adds a vptr (8 B) | indirect call (see M14) |
| Initialising in the body instead of the init list | — | default-construct + assign (double work for strings/vectors) |
| `const` | — | zero runtime cost |

## Pitfalls interviewers ask
1. **Init-list order ≠ declaration order** → reading uninitialised members (`-Wreorder`).
2. **Non-explicit single-arg constructors** → silent conversions (`Rotation2D r = 90;`).
3. **Missing `const` on getters** → unusable through `const&`, and it spreads non-constness across the code.
4. **Public data in a class with an invariant**: anyone can break it (`q.w = 2`).
5. **Zombie objects** (`bool ok_`) instead of failing construction.
6. **Unchecked `operator[]` on grids**: off-by-one gives silent heap corruption. Provide a checked `at()` path.
7. **`(int)x` vs `std::floor(x)`** for negative world coordinates in grid indexing.
8. **Calling virtual functions from constructors** dispatches to the base version (see M13/M14).

## Robotics angle
- Value types with invariants: `UnitQuaternion`, `SO2`/`SO3`, `Pose2` (angle wrapped), `Covariance` (symmetric PSD).
- Maps and grids: bounds-checked access, clamped log-odds, row-major storage, `worldToCell` with `floor`.
- Sensor configs: validate in the constructor or a factory (rate > 0, intrinsics positive), so later code never re-checks.
- Embedded/real-time code often builds with `-fno-exceptions`: use factories returning `std::optional`/`expected` and private constructors.

## Rapid-fire questions
<details><summary>Show answers</summary>

- *What is an invariant?* A condition that holds for every object between public calls (e.g. ‖q‖ = 1). Constructors establish it; mutators preserve it.
- *Why use initializer lists?* They initialise directly (no default construction + assignment) and are required for const, reference, and non-default-constructible members.
- *In what order are members initialised?* Declaration order. Destruction runs in reverse.
- *What does `explicit` do?* It forbids using the constructor for implicit conversions and copy-initialisation.
- *What does a `const` member function guarantee?* `this` is `const T*`, so it can't modify non-`mutable` members, and it's callable on const objects.
- *When is the default constructor not generated?* When you declare any other constructor (bring it back with `= default`).
- *`static` member function vs free function?* A static member has access to private members and lives in the class scope; there's no `this`.
- *How do you fail a constructor?* Throw. The destructor won't run, but already-built members are destroyed.
</details>

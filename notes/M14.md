# M14 · Polymorphism: virtual, override, abstract classes, vtables, slicing, virtual dtor

## Core ideas
```cpp
struct Sensor {                                  // abstract interface
  virtual ~Sensor() = default;                   // ALWAYS virtual if deleted through Sensor*
  virtual double rate() const = 0;               // pure virtual -> class is abstract
  virtual std::string name() const { return "sensor"; }   // overridable default
  virtual std::unique_ptr<Sensor> clone() const = 0;      // "virtual copy constructor"
};
struct Lidar final : Sensor {                    // final: no further overriding, enables devirtualization
  double rate() const override { return 10.0; }  // override: compile error if signature doesn't match
  std::unique_ptr<Sensor> clone() const override { return std::make_unique<Lidar>(*this); }
};

std::vector<std::unique_ptr<Sensor>> rig;        // polymorphic container: store POINTERS
rig.push_back(std::make_unique<Lidar>());
for (const auto& s : rig) s->rate();             // dynamic dispatch through vptr
```

| Keyword | Meaning |
|---|---|
| `virtual` | Call resolved at run time through the vtable |
| `= 0` | Pure virtual; class can't be instantiated |
| `override` | Checks you really override (catches `const`/param mismatches) |
| `final` | Class can't be derived / function can't be overridden |
| `dynamic_cast<D*>(b)` | Checked downcast, `nullptr` on failure (needs ≥1 virtual fn, RTTI) |

### Static vs dynamic binding
```cpp
Lidar l; Sensor& s = l;
s.rate();          // dynamic: Lidar::rate
l.Sensor::name();  // qualified call: always static, bypasses vtable
// Sensor copy = l;   // won't compile (abstract). If Sensor were concrete it would SLICE.
```
Default arguments are bound **statically** (from the static type), even for virtual calls.

## What happens in memory / cost
| Thing | Cost |
|---|---|
| vptr | +8 B per object (first virtual fn), one per polymorphic base |
| vtable | One static table per class, shared by all objects |
| Virtual call | Load vptr → load slot → indirect call (~1–3 ns; blocks inlining unless devirtualized) |
| `dynamic_cast` | String/RTTI walk, much slower than `static_cast`; avoid in hot loops |
| `std::vector<Base>` of derived objects | **Slicing**: only the Base part copied, vptr is Base's |
| Constructor/destructor | vptr points at the class *currently* being constructed → virtual calls inside ctor/dtor don't reach derived |

## Pitfalls interviewers ask
1. **Non-virtual destructor** + `delete base_ptr` → UB; derived dtor never runs (leaks, ASan `new-delete-type-mismatch`).
2. **Slicing**: `Base b = derived;` or passing `Base` by value, or `std::vector<Base>`. Pass by `const Base&` / store `unique_ptr<Base>`.
3. **Missing `override`**: `double rate()` (no `const`) silently declares a *new* function that hides the base one.
4. **Calling virtual from ctor/dtor** → base version (or pure-virtual call crash).
5. **Default args on virtuals** come from the static type.
6. **Name hiding**: a derived `f(int)` hides all base `f` overloads → `using Base::f;`.
7. **Copying a polymorphic object** via `Base&` → need `clone()`; copying `vector<unique_ptr<Base>>` requires a deep copy loop.
8. **Rule of 5 + virtual dtor**: declaring `virtual ~Base() = default;` suppresses implicit move; add `= default` moves if needed.

## Robotics angle
- Factor graphs (GTSAM-style): `NonlinearFactor` base with virtual `error()`/`linearize()`, factors stored as `shared_ptr`.
- Sensor drivers / filters / plugins (ROS pluginlib) are abstract interfaces + factories.
- Hot inner loops (per point) avoid virtual calls: make the virtual call per *batch* (`apply(cloud)`), or use templates (static polymorphism, CRTP) instead.
- `clone()` lets you deep-copy a configuration graph (e.g. snapshot the optimizer problem).

## Rapid-fire questions
<details><summary>Show answers</summary>

- *How is a virtual call implemented?* Object holds a vptr to its class's vtable; call loads the slot and jumps indirectly.
- *When must a destructor be virtual?* When objects are deleted through a base pointer (any polymorphic base meant for ownership by base pointer).
- *Can constructors be virtual?* No. Use a factory or `clone()`.
- *What is slicing?* Copying a derived object into a base object: derived members and behaviour are lost.
- *Abstract class vs interface?* C++ has no keyword; an "interface" is an abstract class with only pure virtuals and a virtual dtor.
- *Size of an empty class with one virtual function?* 8 (the vptr) on 64-bit.
- *Static vs dynamic polymorphism?* Templates/CRTP resolve at compile time (inlinable, code bloat); virtual resolves at run time (one binary, heterogeneous containers).
- *What does `final` buy you?* Design intent + lets the compiler devirtualize calls.
</details>

# M19 · Advanced STL: custom comparators, hashing, priority_queue

## Core ideas
```cpp
// priority_queue<T, Container, Compare>: Compare = "less important than" -> top() is the LARGEST by default
std::priority_queue<int> maxh;                                          // max-heap
std::priority_queue<int, std::vector<int>, std::greater<int>> minh;     // min-heap

struct Event { double t; int sensor; };
auto later = [](const Event& a, const Event& b) { return a.t > b.t; };  // earliest on top
std::priority_queue<Event, std::vector<Event>, decltype(later)> events(later);

// k nearest with a bounded MAX-heap of size k: top = current worst of the best k
if (heap.size() < k) heap.push({d2, i});
else if (d2 < heap.top().first) { heap.pop(); heap.push({d2, i}); }      // O(n log k)

// Custom hash for unordered_map keys
struct Cell { int x, y; bool operator==(const Cell& o) const { return x == o.x && y == o.y; } };
struct CellHash {
  std::size_t operator()(const Cell& c) const noexcept {
    std::size_t h = std::hash<int>{}(c.x);
    return h ^ (std::hash<int>{}(c.y) + 0x9e3779b97f4a7c15ULL + (h << 6) + (h >> 2));  // boost::hash_combine
  }
};
std::unordered_map<Cell, int, CellHash> occupancy;

// Ordered containers with a custom comparator (must be a strict weak ordering)
auto byRange = [](const Point& a, const Point& b) { return a.r < b.r; };
std::set<Point, decltype(byRange)> s(byRange);
std::sort(v.begin(), v.end(), [](auto& a, auto& b) { return std::tie(a.x, a.y) < std::tie(b.x, b.y); });
```

## What happens in memory / cost
| Container / op | Complexity | Notes |
|---|---|---|
| `priority_queue` push/pop | O(log n) | Binary heap in a `vector` (contiguous, cache-friendly); `top` O(1) |
| `make_heap` | O(n) | Faster than n pushes |
| No decrease-key | – | Dijkstra: push duplicates, skip stale entries (`if (d > dist[u]) continue;`) |
| `unordered_map` find | O(1) avg, O(n) worst | Node-based: one allocation per element; bad hash → all in one bucket |
| `map`/`set` find | O(log n) | Red-black tree, node per element |
| `nth_element` | O(n) avg | Alternative to heaps when you have all data and k is large |
| `partial_sort` | O(n log k) | Top-k sorted |

## Pitfalls interviewers ask
1. **Comparator direction**: `priority_queue` with `less` gives a *max*-heap. For a min-heap use `greater` / `a > b`.
2. **Strict weak ordering**: `<=` in a comparator is UB for sort/set (can crash `std::sort`). Ties must compare false both ways.
3. **Hash/equality mismatch**: equal keys must have equal hashes; you need both `operator==` (or `KeyEqual`) and the hash.
4. **Weak hashes**: `x ^ y` maps `(a,b)` and `(b,a)` to the same bucket, and `(k,k)` to 0. Combine with shifts/multiplication.
5. **Hashing floats**: `-0.0 == 0.0` but different bits, and NaN != NaN. Quantize to integer cell indices first.
6. **Dijkstra with negative edges** is wrong. Use Bellman-Ford.
7. **Stale heap entries** in lazy Dijkstra: forget the `continue` and you get O(E log E) at best, wrong relaxations at worst.
8. `priority_queue` has no iteration and no `clear()`; `top()` on empty is UB.
9. `unordered_map::operator[]` inserts a default value. Use `find`/`count`/`at` for lookups.

## Robotics angle
- **Voxel / occupancy hashing**: `unordered_map<VoxelKey, Voxel, VoxelHash>` (VoxelHashing, OpenVDB-lite, LIO maps).
- **kNN** for normals and ICP correspondences: bounded max-heap of size k (exactly what KD-trees do internally).
- **Event schedulers / sensor sync**: min-heap keyed on timestamp; k-way merge of sorted sensor streams.
- **Path planning**: Dijkstra/A* on a grid or a waypoint graph with `priority_queue<pair<double,int>, ..., greater<>>`.

## Rapid-fire questions
<details><summary>Show answers</summary>

- *Default priority_queue order?* Max-heap (`std::less`), so `top()` is the largest.
- *How do you make a min-heap?* `std::priority_queue<T, std::vector<T>, std::greater<T>>`, or a lambda `a > b`.
- *Complexity of top-k via heap?* O(n log k) time, O(k) memory.
- *What does a hash function need?* Deterministic, equal keys give equal hashes, good spread, `noexcept`, cheap.
- *Why does Dijkstra fail with negative weights?* A settled node could later be improved, which breaks the greedy invariant.
- *Load factor?* size / bucket_count. It triggers a rehash above `max_load_factor()` (default 1.0) and invalidates iterators.
- *When pick map over unordered_map?* Ordered iteration, range queries (`lower_bound`), worst-case guarantees, or no good hash.
- *Why `std::tie` in comparators?* Lexicographic compare of several fields, correct by construction.
</details>

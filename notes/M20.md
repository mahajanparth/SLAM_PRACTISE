# M20 · Interview Practice (C++): strategy + checklist

## Core ideas: the 45-minute loop
| Minute | Do | Say out loud |
|---|---|---|
| 0–5 | **Clarify**: input sizes, sortedness, units, frames, empty/degenerate input, return on failure, ties | "Can the input be empty? Are stamps sorted? What should I return if there's no answer: `optional`, `-1`, throw?" |
| 5–8 | **Examples**: one normal case and one edge case, worked by hand | "For `[1,3],[2,5]` I expect `[1,5]`, and touching intervals `[1,2],[2,3]` merge too, right?" |
| 8–12 | **Approach + complexity** before typing; mention the brute-force baseline | "Brute force is O(n²). Sorting first gives O(n log n), and a heap would give O(n log k)." |
| 12–35 | **Code**: signatures first, small helpers, clear names, `const&` params | Narrate invariants: "`head_` always points at the oldest element." |
| 35–42 | **Test**: run your examples, then edge cases; read the code line by line | "Empty, one element, all equal, negative coords, angle wrap at ±π, k > n." |
| 42–45 | **Follow-ups**: scaling, threading, memory, real-time | "For 1M points I'd use a KD-tree. Multi-threaded, I'd shard by cell." |

### Signature checklist
```cpp
[[nodiscard]] std::optional<Pose2> poseAt(const std::vector<StampedPose>& traj, double t);  // const& in, value out
void scaleInPlace(std::vector<Point3>& cloud, double s);       // non-const & = "I modify this"
std::unique_ptr<Factor> parseFactor(std::string_view line);    // ownership in the type
class Matrix { public: Matrix(Matrix&&) noexcept; ... };       // noexcept moves -> vector uses them
```

## What happens in memory / cost (numbers to quote)
| Operation | Cost |
|---|---|
| L1 / L2 / L3 / DRAM | ~1 ns / 4 ns / 15 ns / 80–100 ns |
| `malloc` + `free` | ~20–100 ns |
| Virtual call / `std::function` call | ~1–3 ns (blocks inlining) |
| Uncontended mutex | ~20 ns; thread creation ~10–50 µs |
| `unordered_map` lookup | ~20–100 ns (hash + cache miss) vs `vector` index ~1 ns |
| `std::list` traversal | cache miss per node; prefer `vector` unless you need stable iterators/O(1) splice |
| 1M `Point3` (24 B) | 24 MB; one pass ~5–10 ms at -O2 |

## Pitfalls interviewers ask
1. **Not clarifying**: silently assuming sorted input or that intervals are half-open.
2. **Edge cases**: empty input, n = 1, duplicates and ties, `size() - 1` underflow, k > n, division by zero (`dt == 0`).
3. **Angles**: never interpolate or average raw angles; wrap the difference to (−π, π].
4. **Floating point**: compare with tolerances; squared distances avoid `sqrt`.
5. **Iterator invalidation** in LRU caches: store `list` iterators in the map (`list` iterators stay valid on splice).
6. **Rule of 0/3/5**: a raw owning pointer member needs all five (or just use `std::vector`/`unique_ptr` → Rule of 0).
7. **Self-assignment and moved-from state**: leave moved-from objects valid (empty).
8. **Complexity of the STL call you used**: `std::list::size` is O(1) since C++11, `std::remove` doesn't erase, and `map::operator[]` inserts.

## Robotics angle: problems you'll see, phrased this way
| Prompt | Core technique |
|---|---|
| "Cache the most recent map tiles" | LRU = `std::list` + `unordered_map<Key, list::iterator>`, custom hash |
| "Sensor was down during these windows, compute uptime" | Sort + merge intervals, binary search, two-pointer intersection |
| "Get the robot pose at the lidar timestamp" | `lower_bound` on stamps + lerp position + shortest-arc yaw (or slerp) |
| "Top-k most observed landmarks" | `unordered_map` count + bounded min-heap / `nth_element` |
| "Small matrix class" | Rule of Five, `noexcept` moves, operator overloading, dimension checks |
| "Thread-safe queue between driver and estimator" | mutex + condition_variable + close flag |

## How to test live (no framework needed)
```cpp
#include <cassert>
assert(merge({}).empty());                          // empty
assert(near(poseAt(traj, traj[0].t)->x, traj[0].pose.x));   // boundary = sample
assert(near(wrap(interp(+3.1, -3.1, 0.5)), M_PI));  // wrap
// compare against a brute-force version on random input with a fixed seed
```
Say: "I'll write a brute-force reference and compare on random inputs with a fixed seed."

## Rapid-fire questions
<details><summary>Show answers</summary>

- *How do you start when the problem is vague?* Restate it, ask about sizes, ordering, edge-case semantics, and the error-return style.
- *How do you talk about complexity?* Time and space, best/average/worst if they differ, and the n you expect (scan = 1e5, map = 1e7).
- *When do you optimize?* After it is correct and tested; name the bottleneck (allocation, cache misses, sqrt) first.
- *What makes an LRU O(1)?* A hash map to list iterators; `splice` moves a node to the front without reallocating.
- *Why `noexcept` moves?* `std::vector` reallocation uses move only if it can't throw, otherwise it copies.
- *How do you interpolate a pose?* Lerp the translation; shortest-arc for yaw (SO(2)), slerp for quaternions; never extrapolate silently.
- *What if you're stuck?* Say what you know, solve a smaller case, write brute force, then improve. Silence is the worst signal.
</details>

     0, 1, 0,

### Skew / hat and vee
$$[\mathbf a]_\times=\begin{bmatrix}0&-a_z&a_y\\a_z&0&-a_x\\-a_y&a_x&0\end{bmatrix},\qquad [\mathbf a]_\times\mathbf b=\mathbf a\times\mathbf b,\qquad [\mathbf a]_\times^T=-[\mathbf a]_\times$$
`vee(S) = (S(2,1), S(0,2), S(1,0))`. Robust version averages: `0.5*(S(2,1)-S(1,2))`, and so on.

### Solving $Ax=b$ (never `A.inverse()*b`)
| Decomposition | Needs | Cost (n×n) | Robustness | Call |
|---|---|---|---|---|
| `llt()` | SPD | $n^3/3$ (fastest) | fails if not SPD, so check `info()` | `A.llt().solve(b)` |
| `ldlt()` | PSD / semi-definite | ~$n^3/3$ | pivoting, handles PSD | `A.ldlt().solve(b)` |
| `partialPivLu()` | invertible | $2n^3/3$ | ok | `A.lu().solve(b)` |
| `colPivHouseholderQr()` | any | ~$4n^3/3$ | rank-revealing | `A.colPivHouseholderQr().solve(b)` |
| `jacobiSvd(ComputeThinU\|ComputeThinV)` | any | ~$10\text{–}20\,n^3$ | most robust, min-norm LS | `.solve(b)` |
| `BDCSVD` | any, large | faster than Jacobi for big n | robust | same |

**Least squares** $\min\|Ax-b\|$, $A\in\mathbb R^{m\times n}$, $m>n$:
- Normal equations $A^TAx=A^Tb$ → `(A.transpose()*A).ldlt().solve(A.transpose()*b)`. Fast, but $\kappa(A^TA)=\kappa(A)^2$.
- QR: `A.colPivHouseholderQr().solve(b)`. Error is $\sim\kappa\,\varepsilon$ instead of $\kappa^2\varepsilon$.
- SVD gives the **minimum-norm** solution when $A$ is rank deficient.

### Rule of 5 (owning raw resource)
```cpp
class Buf {
  float* d_ = nullptr; std::size_t n_ = 0;
 public:
  explicit Buf(std::size_t n) : d_(n ? new float[n]() : nullptr), n_(n) {}
  ~Buf() { delete[] d_; }
  Buf(const Buf& o) : Buf(o.n_) { std::copy(o.d_, o.d_ + n_, d_); }
  Buf(Buf&& o) noexcept : d_(std::exchange(o.d_, nullptr)), n_(std::exchange(o.n_, 0)) {}
  Buf& operator=(Buf o) noexcept { swap(o); return *this; }   // copy-and-swap: copy AND move assign
  void swap(Buf& o) noexcept { std::swap(d_, o.d_); std::swap(n_, o.n_); }
};
```
Rule of zero: `std::unique_ptr<float[]>` or `std::vector<float>` and write nothing.

## What happens in memory / cost
| Thing | Memory | Note |
|---|---|---|
| `Matrix3d` | 72 B inline, stack | loops unrolled, no malloc |
| `Matrix4d`, `Vector4d`, `Vector2d` | 16-B aligned (SSE/AVX) | "fixed-size vectorizable" |
| `MatrixXd(3,3)` | 24 B header + heap 72 B | malloc per temporary |
| `Vector3d` | 24 B, not vectorizable | no alignment issue |
| Storage order | **column-major** by default | inner loop over rows: `for j: for i: A(i,j)` |
| `auto C = A*B;` | expression object, no matrix | re-evaluated (or dangles) on each use |
| `A = A.transpose()` | aliasing → garbage | use `transposeInPlace()` |
| `C.noalias() = A*B` | skips temporary | only if C doesn't alias A or B |

## Pitfalls interviewers ask
1. **Uninitialized fixed-size**: `Matrix3d M;` is garbage. Use `::Zero()`/`::Identity()`.
2. **`auto` + expression templates** → lazy, re-evaluated with *current* operands, or dangling references to temporaries. Write `.eval()` or name the type.
3. **Aliasing** in `A = A.transpose()` / `A = A * A` blocks: Eigen assumes no aliasing for coefficient-wise ops. Matrix products are evaluated into a temporary by default.
4. **Alignment pre-C++17**: a struct with a `Vector4d`/`Matrix4d`/`Quaterniond` member in a `std::vector` or allocated with `new` needs `EIGEN_MAKE_ALIGNED_OPERATOR_NEW` / `aligned_allocator`. C++17 aligned `new` fixes it.
5. **Pass fixed-size Eigen by `const&`** (pass-by-value alignment issues; copies).
6. **`v(3)` on a `Vector3d`**: assert in debug, silent UB with `-DNDEBUG`.
7. **LLT on non-SPD**: no throw; `llt.info() != Eigen::Success` and garbage result.
8. **Rule of 5**: double free from a shallow copy; self-assignment; moved-from state must be valid; move ops must be `noexcept` so `std::vector` moves instead of copying on reallocation.

## Robotics angle
- `skew` appears in SO(3) exp/log, cross-product Jacobians: $\partial(R\,p)/\partial\delta\theta = -R[p]_\times$ (right perturbation).
- Gauss-Newton/LM: solve $H\,\delta=-g$ with `ldlt()` ($H$ is PSD). Sparse SLAM uses `SimplicialLDLT`/CHOLMOD with fill-reducing ordering (AMD/COLAMD).
- Sensor buffers: zero-copy with `Eigen::Map<const Eigen::Matrix3Xf>(ptr, 3, n)`.
- Map points and keyframes: IDs into owning arenas, or `shared_ptr` one way plus `weak_ptr` back. Never `shared_ptr` both ways.
- Timestamp interpolation of poses: lerp translation, **slerp** rotation.

## Rapid-fire questions
<details><summary>Show answers</summary>

- *Matrix3d vs MatrixXd?* Compile-time size on the stack with unrolled ops, vs runtime size on the heap.
- *`const` member function / `mutable`?* It can't modify members; `mutable` members (caches, mutexes) are exempt.
- *`reserve` vs `resize`?* `reserve` sets capacity only (size unchanged); `resize` changes size and constructs elements.
- *What does `std::move` do?* It's only a cast to an rvalue reference. The move ctor or assignment does the moving.
- *Eigen default storage order?* Column-major, so iterate over rows in the inner loop and use `.col(j)` for points in a `Matrix3Xd`.
- *Why avoid `A.inverse()`?* It's slower, less accurate, and you rarely need the inverse itself, only a solve.
- *Why does the normal-equations approach lose accuracy?* It squares the condition number.
- *Why `noexcept` move?* `std::vector` reallocation only moves elements if the move can't throw (strong guarantee); otherwise it copies.
</details>

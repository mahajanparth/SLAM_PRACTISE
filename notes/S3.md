# S3 · Rigid Transforms: SE(3), frame chains, SE(2)

## Core ideas
$$T_{ab}=\begin{bmatrix}R_{ab}&\mathbf t_{ab}\\\mathbf 0^T&1\end{bmatrix}\in SE(3),\qquad p_a=T_{ab}\,p_b=R_{ab}p_b+\mathbf t_{ab}$$
`T_a_b` maps coordinates **from frame b to frame a**. Equivalently, it is the pose of b expressed in a ($\mathbf t_{ab}$ = origin of b in a).
**Subscripts cancel:** $T_{ac}=T_{ab}T_{bc}$, $T_{ba}=T_{ab}^{-1}$.

| Operation | Formula | Cost |
|---|---|---|
| Compose | $(R_1,\mathbf t_1)(R_2,\mathbf t_2)=(R_1R_2,\ R_1\mathbf t_2+\mathbf t_1)$ | 27 + 9 mul |
| Inverse | $(R,\mathbf t)^{-1}=(R^T,\ -R^T\mathbf t)$ | no 4×4 inversion! |
| Point | $R\mathbf p+\mathbf t$ | 9 mul |
| Direction / normal | $R\mathbf v$ (homogeneous $w=0$) | translation ignored |
| Relative motion | $T_{ab}=T_{wa}^{-1}T_{wb}$ | |
| Prediction | $T_{wb}=T_{wa}T_{ab}$ | |
| Plane $(\mathbf n,d)$, $\mathbf n^T\mathbf x+d=0$ | $\mathbf n_B=R\mathbf n_A,\ d_B=d_A-\mathbf n_B^T\mathbf t$ (i.e. $\pi_B=T_{BA}^{-T}\pi_A$) | |

```cpp
Eigen::Isometry3d T = Eigen::Isometry3d::Identity();   // 4x4 storage, knows it's rigid
T.linear() = R; T.translation() = t;   // or T.rotate(q).pretranslate(t)
T.inverse();          // Isometry: uses R^T (cheap). Affine3d::inverse() does a general inverse.
T * p;                // point (applies t);   T.linear() * v  for directions
T.matrix();           // Matrix4d
// batch: one GEMM instead of N small products, no per-point allocation
Eigen::Matrix3Xd Q = (T.linear() * P).colwise() + T.translation();
// zero-copy over a sensor buffer (x, y, z, intensity) floats:
Eigen::Map<const Eigen::Matrix<float, 3, Eigen::Dynamic>, 0, Eigen::OuterStride<4>> P(buf, 3, n);
```

### SE(2) odometry (unicycle, constant $v,\omega$ over $\Delta t$)
$$\begin{aligned}x'&=x+\tfrac{v}{\omega}\big(\sin(\theta+\omega\Delta t)-\sin\theta\big)\\ y'&=y-\tfrac{v}{\omega}\big(\cos(\theta+\omega\Delta t)-\cos\theta\big)\\ \theta'&=\operatorname{wrap}(\theta+\omega\Delta t)\end{aligned}$$
For $|\omega|\to0$, use $x'=x+v\Delta t\cos\theta$, … (the limit, or a Taylor expansion with the midpoint angle).
Wrap with `std::atan2(std::sin(a), std::cos(a))` or `std::remainder(a, 2*M_PI)`.
SE(2) compose: $(x_1,y_1,\theta_1)\oplus(x_2,y_2,\theta_2)=(x_1+c_1x_2-s_1y_2,\ y_1+s_1x_2+c_1y_2,\ \operatorname{wrap}(\theta_1+\theta_2))$.

## Pitfalls interviewers ask
1. **Order of composition**: `T_w_c = T_w_r * T_r_c`, not `T_r_c * T_w_r`. Check that the inner subscripts match.
2. Inverting via `matrix().inverse()`: slower and numerically worse than $(R^T,-R^T t)$.
3. Transforming normals/directions with the translation (they need $w=0$).
4. **Averaging 4×4 matrices** doesn't give a rotation. Average R on SO(3) and t separately.
5. SE(2) Euler integration $x \mathrel{+}= v\cos\theta\,\Delta t$ is biased on curves. Use exact arc or midpoint integration.
6. Angle wrap after every update, and when computing **differences** (`wrap(a - b)`).
7. `auto` with Eigen products in transform code, and uninitialized `Isometry3d` (the default ctor leaves R and t uninitialized). Use `::Identity()`.

## Robotics angle
- Extrinsics chain: $T_{c\ell}=T_{wc}^{-1}T_{wr}T_{r\ell}$ to project lidar into a camera image.
- Odometry factor in a pose graph: measurement $\hat T_{ab}$, error $\log(\hat T_{ab}^{-1}T_{wa}^{-1}T_{wb})$.
- Deskewing: per-point $T(t_i)$ via slerp + lerp between scan start and end.
- Plane landmarks (ground, walls) move with $T^{-T}$. Point-to-plane ICP uses the plane in the target frame.

## Rapid-fire questions
<details><summary>Show answers</summary>

- *Params vs DOF of SE(3)?* 6 DOF; 12 meaningful numbers in [R|t] (16 stored), or 7 for quat + t.
- *What does `T_a_b` mean?* It maps points from b to a, i.e. the pose of b in a.
- *Why can't you just average two 4×4 matrices?* The average of two rotations is not orthonormal. Interpolate on the manifold (slerp R, lerp t, or $\exp(t\log)$).
- *Homogeneous w = 0?* A direction or point at infinity, so translation doesn't affect it.
- *Inverse of [R|t]?* $[R^T \mid -R^Tt]$.
- *Isometry3d vs Affine3d?* Isometry assumes rigid, so `inverse()` uses the transpose. Affine allows scale and shear.
- *Relative pose between two keyframes?* $T_{ab}=T_{wa}^{-1}T_{wb}$.
- *Transform a plane?* $\mathbf n'=R\mathbf n$, $d'=d-\mathbf n'^T\mathbf t$.
</details>

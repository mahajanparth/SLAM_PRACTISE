# S5 · Spatial Search & Robust Fitting

## Core ideas

### KD-tree (static, 3D)
```cpp
// Flat nodes + permuted index array; points never move.
struct Node { int axis = -1; double split; int left, right; int begin, end; };  // axis<0 => leaf [begin,end)
int build(int b, int e) {
  if (e - b <= kLeaf) return makeLeaf(b, e);                 // leaf buckets of 8-20 pts
  int axis = maxSpreadAxis(b, e);                            // or depth % 3
  int m = b + (e - b) / 2;
  std::nth_element(idx.begin()+b, idx.begin()+m, idx.begin()+e,
                   [&](int i, int j){ return pts[i][axis] < pts[j][axis]; });   // O(n) median
  ...  // left = [b,m) (<= split), right = [m,e) (>= split). Don't hold Node& across push_back!
}
```
**Pruning rule.** With $\Delta = q_{\text{axis}} - \text{split}$, recurse into the near side first, then visit the far side only if
$$\Delta^2 < d_{\text{best}}^2 \qquad(\text{radius search: } \Delta^2 \le r^2).$$
Every far-side point is at least $|\Delta|$ away along that axis.

| | Build | Query (avg) | Worst query | Insert/delete |
|---|---|---|---|---|
| KD-tree | $O(N\log N)$ | $O(\log N)$ | $O(N)$ (bad splits / high-dim) | rebuild (or ikd-tree) |
| Octree | $O(N\log N)$ | $O(\log N)$ | – | yes; multi-resolution, ray casting |
| Voxel hash | $O(N)$ | $O(27k)$ (approx.) | – | $O(1)$; used by KISS-ICP, local maps |
| Brute force | – | $O(N)$ | $O(N)$ | trivial |

### RANSAC
Sample $s$ points → model → count inliers → keep the best → **refit with least squares** on the inliers.
$$N = \frac{\log(1-p)}{\log\!\left(1-w^{s}\right)}\qquad(p=0.99,\; s=3:\; w=0.5\to 35,\; w=0.3\to 169)$$
Plane from 3 points: $n = (p_2-p_1)\times(p_3-p_1)$. Reject if $\lVert n\rVert \approx 0$ (collinear or duplicate), then $\hat n = n/\lVert n\rVert$ and $d = -\hat n\cdot p_1$.
Use your **own** `std::mt19937 rng(seed)` so runs are reproducible, never `rand()`.

### Total least squares (plane / line)
$$\mu = \tfrac1N\textstyle\sum p_i,\qquad C = \sum (p_i-\mu)(p_i-\mu)^\top = V\Lambda V^\top,\ \lambda_0\le\lambda_1\le\lambda_2$$
Plane normal = $v_0$, $d=-v_0\cdot\mu$. Line = $(\mu, v_2)$. Residual: $\lambda_0/N$ = mean squared distance.
```cpp
Eigen::SelfAdjointEigenSolver<Eigen::Matrix3d> es(C);   // ascending eigenvalues, eigvecs in COLUMNS
Eigen::Vector3d n = es.eigenvectors().col(0);
```
Degenerate if $\lambda_1 \le \varepsilon\lambda_2$ (collinear, so the plane is undefined) or $\lambda_2 \approx 0$ (all identical).

### Union-find (Euclidean clustering)
```cpp
int find(int x) { while (p[x] != x) { p[x] = p[p[x]]; x = p[x]; } return x; }   // path halving, iterative
bool unite(int a, int b) { a = find(a); b = find(b); if (a == b) return false;
  if (sz[a] < sz[b]) std::swap(a, b); p[b] = a; sz[a] += sz[b]; return true; }  // union by size
```
Neighbours: voxel hash with side $r$ (key = `floor(p/r)`, which handles negative coordinates) and check 27 cells. Pairs `j > i`, `squaredNorm() <= r*r`.

### Algebraic sphere fit
$$\lVert p\rVert^2 = 2c\cdot p + k,\quad k = r^2-\lVert c\rVert^2 \;\Rightarrow\; [\,2p_i^\top\;\;1\,]\begin{bmatrix}c\\k\end{bmatrix} = \lVert p_i\rVert^2$$
Solve with `colPivHouseholderQr()`, check `rank()==4` (coplanar points give rank 3), and centre the data first.

## What happens in memory / cost
| Thing | Cost / note |
|---|---|
| `nth_element` | $O(n)$ average, which keeps the build at $O(N\log N)$ (sorting at each level gives $O(N\log^2N)$) |
| Node as `unique_ptr` children | one malloc per node, pointer chasing → cache misses. Prefer a flat `vector<Node>` |
| Leaf buckets | fewer nodes, contiguous scans, often 2–3× faster queries than 1-point leaves |
| RANSAC | $O(N_{\text{iter}}\cdot N)$; early exit or subsampled scoring for big clouds |
| PCA fit | one pass to build $C$ ($O(N)$) + a 3×3 eigen-solve (constant) |
| `unordered_map<Vector3i, …>` | needs a custom hash (e.g. primes 73856093, 19349663, 83492791 XOR) |

## Pitfalls interviewers ask
1. Comparing `|diff|` with **squared** best distance in KD-tree pruning.
2. Holding `Node&` across `nodes_.push_back` in a recursive build (reallocation → dangling).
3. Recursion depth / infinite recursion with **duplicate points** when splitting by value instead of by count.
4. RANSAC sampling the same index twice → zero normal → NaN plane. Check distinctness and $\lVert n\rVert$.
5. Fitting $z = ax+by+c$: fails for vertical planes and minimises vertical, not orthogonal, error.
6. Not centring before covariance: $\sum pp^\top - N\mu\mu^\top$ cancels catastrophically at map scale (~10⁴ m).
7. Voxel key with `int(p/r)` truncates towards 0, so cells −0.5 and +0.5 merge. Use `std::floor`.
8. Union-find recursion `find` on a 10⁵ chain without compression → stack overflow.

## Robotics angle
- **ICP / LOAM**: NN queries every iteration, using a KD-tree (FLANN/nanoflann), ikd-tree (FAST-LIO2) or voxel hash (KISS-ICP).
- **Ground segmentation**: RANSAC plane (or Patchwork++), then Euclidean clustering for objects (PCL `EuclideanClusterExtraction`).
- **Normals and curvature**: PCA on kNN patches. $\lambda_0/\sum\lambda$ classifies edge vs planar points.
- **Calibration**: sphere/circle targets (algebraic fit + RANSAC + GN refine).
- **Multiple planes**: run RANSAC, remove inliers, repeat (walls, floor, ceiling).

## Rapid-fire questions
<details><summary>Show answers</summary>

- *KD-tree vs octree vs voxel hash?* KD-tree: exact NN on static data. Octree: hierarchical occupancy, ray casting, multi-resolution. Voxel hash: dynamic local maps with O(1) insert/delete and approximate neighbourhoods.
- *Why RANSAC over least squares with outliers?* LS has 0% breakdown point. RANSAC's 0/1 scoring bounds outlier influence.
- *RANSAC iteration formula?* $N=\log(1-p)/\log(1-w^s)$.
- *How to make RANSAC better?* LS refit on inliers (LO-RANSAC), MSAC truncated-quadratic scoring, PROSAC ordered sampling, adaptive $N$.
- *Why do KD-trees degrade in high-D?* The query ball crosses almost every split, so pruning fails. Use approximate NN (FLANN, HNSW).
- *Union-find complexity?* $O(\alpha(n))$ amortised with path compression + union by rank.
- *Line fit vs plane fit eigenvector?* Line = largest eigenvalue's vector; plane normal = smallest.
- *Algebraic vs geometric sphere fit?* Algebraic is linear and closed-form but biased for partial or noisy data. Refine geometrically with GN.
</details>
